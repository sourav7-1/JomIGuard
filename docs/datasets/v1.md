# Dataset card: synthetic v1

**Manifest:** `ml/datasets/v1.json` (recipe, environment, counts, and a sha256 for every file).
**Data:** `data/` (gitignored, so regenerate it locally). **Built:** 2026-10-09.

## What it contains

Synthetic, rendered Bangla land documents with ground-truth JSON that validates against
`backend/app/schemas/extracted.py`. All names, numbers and places are synthetic samples; no real
records, NID, phone or birth registration numbers. Every image carries a "নমুনা / SAMPLE" footer.

| folder | content |
|---|---|
| `data/synthetic/khatian/` | 50 clean khatians (CS/SA/RS/BS): `{id}.png` + `{id}.json` (`KhatianData`), `manifest.csv` |
| `data/synthetic/cases/` | 50 cases, one folder each: `khatian.png/json`, `deed.png/json` (`DeedData`), `case.json` (mismatch labels), `manifest.csv` |
| `data/augmented/` | 300 phone-photo copies of all 150 clean images (2 each): `{source_id}_{doc}_{k}.png`, source JSON copied unchanged, `manifest.csv` with the applied parameters, `contact_sheet.png` |

Deed ground truth records what the deed *prints*, including injected errors. `case.json` holds
the label: `mismatches: [{type, field, khatian_value, deed_value}]`.

## How to regenerate

From `ml/`:

```bash
PYTHONPATH=../backend uv run python -m synth.khatian --n 50 --seed 42 --out ../data/synthetic/khatian
PYTHONPATH=../backend uv run python -m synth.deed --n 50 --seed 43 --mismatch-rate 0.4 --out ../data/synthetic/cases
uv run python -m synth.augment --per-source 2 --seed 44 --src ../data/synthetic --out ../data/augmented
uv run python -m synth.dataset verify --version v1   # checks a fresh regeneration against v1.json
```

`verify` regenerates everything in a temp folder. JSON and CSV files must match the recorded
sha256 exactly (otherwise it fails). PNG differences only produce a warning with a count, since
font rendering and image codecs can differ by machine. Missing or extra files fail.

Built with Python 3.12.14, Playwright 1.63.0 (Chromium 153.0.8010.12), albumentations 2.0.8,
opencv-python-headless 5.0.0.93, numpy 2.5.3 on Windows 11. On the build machine, verify
reproduced all 954 files byte-for-byte, PNGs included.

## Train/test split

The split is assigned **per source**, not per image: a source is one standalone khatian
(`khatian_00001`) or one case (`case_00001`, covering both its khatian and its deed). The rule is
`sha256("44:split:{source_id}")`; the first 4 bytes / 2³² < 0.8 → `train`, else `test`
(`synth.augment.split_for`, seed 44). Every augmented copy of a source, and the clean source
images themselves (see `split` in `v1.json`), share that source's split, so no document appears
in both train and test.

## Known limits

- **Synthetic only.** No real documents. Layouts, names and numbers are invented; real-world
  accuracy must be measured on real (consented) documents.
- **One layout per document type.** Real khatians and deeds vary by survey, era, office and
  printer; a model trained on v1 may overfit this layout.
- **Printed text only.** No handwriting, stamps, signatures, or handwritten corrections.
- **No mutation/DCR or heir certificate images yet.** Only khatians and sale deeds are rendered.
- **Units limited to একর and শতাংশ.** No বিঘা, কাঠা or আনা in the images.
- **Small and imbalanced.** 50 cases; some mismatch types have only 1–4 examples (e.g. one
  `khatian_mismatch`), and the benign honorific variation appears only in clean deeds.
- **Built from uncommitted code.** `v1.json` records commit `25781cb` with `dirty: true`.
