# Dataset card: synthetic v2

**Manifest:** `ml/datasets/v2.json` (recipe, environment, counts, and a sha256 for every file).
**Data:** `data/` (gitignored, so regenerate it locally). **Built:** 2026-10-15. Supersedes v1.

## What it contains

Synthetic, rendered Bangla land documents with ground-truth JSON that validates against
`backend/app/schemas/extracted.py`. All names, numbers and places are synthetic samples; no real
records, NID, phone or birth registration numbers. Every image carries a "নমুনা / SAMPLE" footer.
New in v2: a mutation khatian with DCR receipt in every case, and an heir certificate in family
cases.

| folder | content |
|---|---|
| `data/synthetic/khatian/` | 50 clean khatians (CS/SA/RS/BS): `{id}.png` + `{id}.json` (`KhatianData`), `manifest.csv` |
| `data/synthetic/cases/` | 50 cases, one folder each: `khatian.png/json`, `deed.png/json` (`DeedData`), `mutation.png/json` (`MutationData`), in family cases `heir_cert.png/json` (`HeirCertData`), `case.json` (mismatch labels and the list of documents), `manifest.csv` |
| `data/augmented/` | 456 phone-photo copies of all 228 clean images (2 each): `{source_id}_{doc}_{k}.png`, source JSON copied unchanged, `manifest.csv` with the applied parameters, `contact_sheet.png` |

Deed ground truth records what the deed *prints*, including injected errors. `case.json` holds
the label: `mismatches: [{type, field, khatian_value, deed_value}]`.

**Family cases** (28 of 50): the khatian owners are the children (and sometimes the widow) of one
deceased father. The deed's `title_source_text` says ওয়ারিশ সূত্রে প্রাপ্ত, the mutation's
`basis_text` is ওয়ারিশ সূত্রে, and the heir certificate lists every owner as an heir. Other cases say
ক্রয় সূত্রে and have no heir certificate. The mutation copies the case khatian's location, owners,
shares and plots (`new_khatian_no` = `khatian_no`); its area unit is printed only in the column
header (`area_unit_text` = `"একর"`).

## How to regenerate

From `ml/`:

```bash
PYTHONPATH=../backend uv run python -m synth.khatian --n 50 --seed 42 --out ../data/synthetic/khatian
PYTHONPATH=../backend uv run python -m synth.deed --n 50 --seed 43 --mismatch-rate 0.4 --out ../data/synthetic/cases
uv run python -m synth.augment --per-source 2 --seed 44 --src ../data/synthetic --out ../data/augmented
uv run python -m synth.dataset verify --version v2   # checks a fresh regeneration against v2.json
```

`verify` regenerates everything in a temp folder. JSON and CSV files must match the recorded
sha256 exactly (otherwise it fails). PNG differences only produce a warning with a count, since
font rendering and image codecs can differ by machine. Missing or extra files fail. All JSON and
CSV files are written as UTF-8 with `\n` line endings, so their hashes match on any OS.

Built with Python 3.12.15, Playwright 1.63.0, albumentations 2.0.8, opencv-python-headless
5.0.0.93, numpy 2.5.3, pydantic 2.14.0 on Linux (Docker on WSL2, `python:3.12-slim` / Debian 13).
Chromium was Debian's `chromium` package 155.0.8059.39 (Playwright's own download host was not
reachable from the build network), linked into Playwright's browser path. On the build machine,
verify reproduced all 1422 files byte-for-byte, PNGs included.

## Train/test split

The split is assigned **per source**, not per image: a source is one standalone khatian
(`khatian_00001`) or one case (`case_00001`, covering all its documents). The rule is
`sha256("44:split:{source_id}")`; the first 4 bytes / 2³² < 0.8 → `train`, else `test`
(`synth.augment.split_for`, seed 44). Every augmented copy of a source, and the clean source
images themselves (see `split` in `v2.json`), share that source's split, so no document appears
in both train and test.

## Known limits

- **Synthetic only.** No real documents. Layouts, names and numbers are invented; real-world
  accuracy must be measured on real (consented) documents.
- **One layout per document type.** Real khatians, deeds, mutations and heir certificates vary
  by survey, era, office and printer; a model trained on v2 may overfit these layouts.
- **Printed text only.** No handwriting, stamps, seals, signatures, or handwritten corrections.
- **Units limited to একর and শতাংশ.** No বিঘা, কাঠা or আনা in the images.
- **Small and imbalanced.** 50 cases; some mismatch types have only 3–6 examples, and the
  benign honorific variation appears only in clean deeds. Heir certificates exist only for the
  28 family cases.
- **Consistent families only.** Heir certificates always match the mutation owners; no
  `heir_missing_from_mutation` or `chain_break` examples are generated.
- **Built from uncommitted code.** `v2.json` records commit `a5f4fa3` with `dirty: true`.
